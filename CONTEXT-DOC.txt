3. U-01 — DESIGN SYSTEM — ✅ COMPLETE (THIS SESSION'S DELIVERABLE)
--------------------------------------------------------------------------------
Location: /design-system/avi-tokens.css, /design-system/showcase.html,
/design-system/README.md

What was built, and why, in detail:

3.1 Token architecture
    A single CSS custom-property layer, namespaced `--avi-*`, covering:
      - Background scale (6 steps: base, raised, card, card-hover, input, sink)
      - Text scale (primary, secondary, muted, faint, inverse)
      - Accent gradient system (emerald #34D399 → cyan #06B6D4, plus solid/
        hover/subtle/glow variants) — this is the DrufiyAI "Precision
        Engineering" redesign direction from the user's spec, carried over
        verbatim (same hex values as specified: --accent-start #34D399,
        --accent-end #06B6D4, --accent-solid #3BE8B0).
      - Status colors (live/warning/error/info/idle)
      - Terminal/signal colors (bg/header/text/prompt/command/output/error/
        success/highlight) — feeds the Lear/Prash terminal demo component
        when U-04 builds it, and the "signal map" hero visualization.
      - Border scale (subtle → strong → accent)
      - Shadow scale (sm/md/lg/xl + glow/glow-strong)
      - Typography: three families —
          serif   : 'Instrument Serif' (headlines) — ALSO aliases to
                    'Ogg Medium' so the exact same token can be reused by
                    the future cinematic entry page, which specifically
                    requires the font-family name "Ogg Medium" per its
                    spec (see section 4). This was a deliberate design
                    decision to keep ONE font token working across both
                    the marketing/dashboard UI and the entry cinematic.
          sans    : 'Plus Jakarta Sans' (body/UI)
          mono    : 'IBM Plex Mono' (labels, terminal, code)
        Type scale --avi-text-xs (12px) → --avi-text-8xl (88px), line-height
        scale, letter-spacing scale, weight scale.
      - Spacing: strict 8px base grid, --avi-space-0 → --avi-space-40 (160px),
        plus layout tokens (container max-width 1400px, fluid container
        padding, section/column gap, nav height, and two SIDEBAR WIDTH
        tokens pre-declared for U-02: --avi-sidebar-width (264px) and
        --avi-sidebar-width-collapsed (76px) so the sidebar task has zero
        guesswork about spacing when it starts.
      - Radii: xs(4)→full(9999), matching the spec's pill buttons/inputs/cards.
      - Motion: duration scale (100ms→1200ms), easing curves (ease-out,
        ease-in-out, spring, bounce, "smooth" — this last one is the exact
        `cubic-bezier(0.22, 1, 0.36, 1)` used by the Mostar reference page's
        slider transition, pre-wired for when the entry page is built),
        plus ready-made transition shorthands (--avi-transition-all etc).
      - Z-index scale (base→scene→content→nav→dropdown→sticky→overlay→
        modal→toast→skip) so future layered video/animation work has a
        documented stacking order instead of ad-hoc z-index wars.
      - Gradient tokens built FROM the accent tokens (never hard-coded a
        second time) — accent, accent-reverse, accent-soft, divider sheen.
      - "Live backdrop" tint/scanline tokens — pre-wired for the future
        live-video-behind-everything requirement (section 4/7). Nothing
        renders yet; this just reserves the visual contract (scrim alpha,
        scanline alpha) so video work in a later session matches the rest
        of the system automatically.
      - Runtime/self-adapt placeholders: --avi-fluid-scale,
        --avi-brand-hue-rotate, --avi-brand-name — explicitly reserved for
        the future "avi-adapt.js" fork-detection script described in
        section 4/8. These do nothing yet by themselves; they exist so
        that script has stable hooks to write to without a future agent
        having to invent new token names (which would risk breaking
        whatever components were built against the old names).

3.2 Base layer
    Scoped under a `[data-avi]` attribute selector (not global `*`/`body`)
    specifically so this design system can be embedded into a foreign host
    application without clobbering that host's own CSS — this directly
    services the "paste into another repo and it adapts" requirement.
    Includes: box-sizing reset, font smoothing, selection color, focus
    rings, slim branded scrollbar.

3.3 Primitives (already usable today, before U-04 formalizes a full library)
    .avi-glass / .avi-glass-nav      — glassmorphism surfaces
    .avi-text-gradient / -label      — gradient text utilities
    .avi-divider                     — gradient hairline
    .avi-label                       — mono uppercase section label w/ dot
    .avi-dot[data-state]             — status dot (live/idle/warn/error)
    .avi-tag                         — pill chip (used for Lear/Prash tags)
    .avi-btn (+ --gradient/--outline/--ghost, --sm/--lg) — buttons
    .avi-field/.avi-input/.avi-textarea — form primitives (maps directly to
      the NAME/EMAIL/WHAT ARE YOU WORKING ON? contact form fields)
    .avi-terminal / .avi-terminal-bar / .avi-terminal-body — terminal well,
      pre-styled to reproduce the Lear/Prash terminal demos verbatim
    .avi-backdrop                    — the reserved "black area becomes
      live video" mount primitive: absolutely-positioned video/canvas
      slot at z-index -1 inside the element, plus a scanline+tint scrim
      overlay so ANY future video feed automatically looks "in-system"
      without extra styling. THIS IS NOT YET WIRED TO ANY REAL VIDEO —
      it is the CSS contract the future video script will rely on.
    .avi-skip                        — accessible skip-to-content link

3.4 Resilience already built in
    - `@supports not (backdrop-filter)` fallback (solid fills instead of
      glass blur) for older browsers.
    - `prefers-reduced-motion: reduce` kills all animation/transition
      durations globally in one rule.
    - Verified WCAG AA-oriented contrast choices per the spec's own
      analysis (text-primary ~16:1, text-secondary ~5.8:1, accent ~8.2:1
      against --avi-bg-base).

3.5 Verification performed this session
    Started a local `python3 -m http.server` on port 8080 at the repo root
    and confirmed both `/design-system/avi-tokens.css` and
    `/design-system/showcase.html` return HTTP 200. The showcase page
    renders color swatches, the full type scale, the full spacing scale,
    buttons/tags/dots/dividers/inputs, two example glass cards (one
    generic, one reproducing the exact Lear terminal demo copy), a motion
    demo tile, and an empty "live backdrop" well — all read LIVE from the
    actual CSS custom properties via JS (`getComputedStyle`), so the
    showcase can never silently drift out of sync with the token file.

3.6 Explicit rule for everything built next (U-02/U-03/U-04/entry page)
    NO component, section, or page may hard-code a color, spacing value,
    radius, duration, easing curve, or font-family. Every single visual
    value must resolve through a `var(--avi-...)` token. This is the
    load-bearing mechanism behind the "paste this repo into another app
    and it re-fits automatically" requirement — a future fork-adaptation
    script only has to rewrite a small number of root tokens (accent hues,
    brand name, spacing scale multiplier) for the ENTIRE UI to re-skin
    itself, because every component already points at those tokens instead
    of literal values.

7. "SELF-REDESIGNING ON FORK/PASTE" REQUIREMENT — DESIGN NOTES
--------------------------------------------------------------------------------
User's ask, verbatim intent: if someone copies/pushes this repository into
a DIFFERENT application/repo, the UI should automatically re-fit that new
host app "on its own" while keeping the UI/branding "intact" (i.e. it
still looks like this design system, just correctly scaled/composed for
whatever host DOM it lands in).

Planned mechanism (NOT YET BUILT — reserved for a dedicated future task,
likely bundled with U-04 or its own U-05):
    1. `avi-adapt.js` — a small, dependency-free script that runs on
       page load and:
         a. Detects the host page's existing viewport breakpoints,
            container widths, and any pre-existing brand color (e.g. by
            sampling a `<meta name="theme-color">` or a designated
            `data-avi-host-accent` attribute the integrator can set) and
            maps it onto `--avi-accent-start` / `--avi-accent-end` via a
            hue-rotate/relative-color calculation, writing the result back
            into `--avi-brand-hue-rotate` and the accent tokens.
         b. Detects available width/height of its mount point and adjusts
            `--avi-fluid-scale` so type/spacing scale fluidly rather than
            overflowing a foreign layout.
         c. Reads a `data-avi-brand` attribute (or falls back to the
            existing "DrufiyAI"/"AVI" default) and rewrites
            `--avi-brand-name`, plus swaps any element with
            `data-avi-bind="brand-name"` to that text — this is how logo/
            footer copy can re-point at a new host brand without hand-
            editing every component.
         d. Everything downstream (every component, the entry page, the
            future sidebar/dashboard) must ONLY ever consume `var(--avi-*)`
            tokens (per the rule in section 3.6) — that is what makes step
            (a)-(c) suf1ficient to "redesign" the whole app from one
            script instead of needing to touch every file.
    2. A `postinstall`/`prepare` style hook (framework-dependent, to be
       decided once a host stack is chosen) that runs `avi-adapt.js`'s
       detection logic once at integration time, plus the always-on
       runtime version for pages that load dynamically.
    3. This is inherently a "best-effort" feature — full automatic
       redesign for ARBITRARY unknown host apps is an open-ended problem;
       document constraints clearly to the user (e.g. it re-themes color/
       spacing/typography scale and brand strings; it does NOT rewrite
       arbitrary host HTML structure it doesn't own).
